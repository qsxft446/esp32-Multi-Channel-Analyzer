# MCA на ESP32-S3 + AD9226

Гамма-спектрометр: захват АЦП (LCD_CAM + GDMA), обработка на ядре 1, веб по
WiFi/Ethernet, эмуляция MCA (shproto) на UART0. ESP-IDF 5.4.4. Устройство,
история отладки и найденные причины — в README.md: прежде чем чинить похожее,
прочитать его раздел.

## Команды
- Сборка: `idf.py build` (цель esp32s3). Прошивка `idf.py -p COM3 flash` —
  только по просьбе пользователя: плата у него на столе.
- JS страницы (живёт строками в `main/mca_web.c`): `cd main && python ../check_js.py` (нужен node).
- Обработка на модели: `python tools/test_dsp.py`. Кодек эмуляции: `python tools/emu_check.py --selftest`.
- Страница без платы: `python tools/mkpage.py` → `build/page_test.html`.
- Перевод страниц: `python tools/check_i18n.py` — у каждой русской надписи есть английская.
- Python с русским выводом — с `PYTHONIOENCODING=utf-8`.

## Что держать в согласии
- `tools/dspmodel.py`, `tools/scopemodel.py` — порт `mca_dsp.c` и осциллографа.
  Правка обработки или дефолтов в прошивке → та же правка в модели и прогон `test_dsp.py`.
- README.md и README.en.md — одно содержание; меняется один — меняется второй.
- Поведение для пользователя изменилось → раздел README в том же коммите.
- Страницы прибора на двух языках: новая надпись без английской пары валит `check_i18n.py`.

## Отладка: сначала причина, потом правка
1. Ошибку и лог читать дословно, воспроизвести, посмотреть `git diff` / `git log`.
2. Найти, где именно ломается: профиль `prof:` (`MCA_PROF_LOG 1` в `mca_config.h`),
   страница `/diag`, счётчики потерь чанков.
3. Одна гипотеза — одна проверка — одна переменная. Две неудачные правки подряд —
   стоп и разговор об устройстве, а не третья вслепую.
4. Связь с прибором тормозит — сначала пара «частота АЦП + канал WiFi»
   (README, «Помехи от CLK в WiFi»), потом код.
5. Непроверенное предположение так и называть: предположение.

## Числа и проверки
- «Задано в настройке» ≠ «измерено». CPS, мёртвое время, скорость потока, загрузка
  ядер — только вместе с источником: вывод, замер, `file:line`.
- Таймаут или бюджет времени сравнивать с физическим временем операции — скриптом
  с промежуточными значениями (пример бюджета: 128 мкс на чанк при 16 МГц).
- Тест засчитывается, если показано, что он краснеет на внесённой ошибке.
- Спектр и счёт импульсов сверять двумя независимыми путями (прибор против модели
  или `emu_check.py`), а не одним и тем же кодом.
- Искать тихие ошибки: непроверенный `esp_err_t`, «успех» в логе до проверки,
  счётчики потерь, которые никуда не выводятся.
- Перед долгим прогоном — убедиться, что зависание и перезагрузка оставят след
  (паника Task WDT, coredump, `esp_reset_reason()`).
- «Работает» = что запускалось, сколько, при каких условиях. «Не воспроизвелось» — не вывод.

## Необратимое — только по явному «да» пользователя
`git push`, `--force`, `reset --hard`; `idf.py erase-flash`, стирание NVS, eFuse,
шифрование флеша; прошивка платы. Перед push: в `git add` только нужные пути
(не `-A`), проверка на секреты (пароли WiFi, IP, ключи) по файлам целиком.

## Стиль
- Коммиты по-русски, одна строка, обычно «Область: что сделано» (см. `git log`).
- Комментарии — по-русски, как в окружающем коде.
- Тексты интерфейса — сразу парой русский/английский (см. `LJS` в `mca_web.c`): в разметке
  атрибут `data-en` (для title — `data-en-title`), в скриптах `L('рус','eng')`, справка —
  блоки `lr`/`le`, сообщения прибора в JSON — поля `msg` и `en`.

Часть правил — из github.com/VibeEngineering-LLC/agent-ops-doctrine
(DOCTRINE-CORE §5, §12, §20; skills/firmware-stability), прочитано 2026-09-16.
